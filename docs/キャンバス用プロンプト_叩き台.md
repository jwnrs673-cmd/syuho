# スプレッドシート キャンバス用プロンプト（叩き台）

設計v1のテーブル（`M_案件` / `T_タスク` / `M_大分類` / `M_担当者` / `ダッシュボード`）を前提に、
スプレッドシートのキャンバス（Gemini）へ **そのまま貼って使える** プロンプトをまとめたもの。

- 目的1：キャンバスから **タスクを登録**（`T_タスク` に行追加）
- 目的2：登録結果を **ダッシュボード**（円グラフ＋ドリルダウン）で表示

> 使い方：対象スプレッドシートを開き、キャンバス（Gemini）を起動して下記プロンプトを貼る。
> `【】` の箇所は自分の環境に合わせて調整する。生成物が想定と違うときは「■調整の指示例」を追記する。

---

## 0. 共通の前提ブロック（各プロンプトの先頭に付ける）

キャンバスに“今のテーブル構成”を正しく伝えるための共通説明。プロンプトの冒頭に貼る。

```
あなたはこのスプレッドシートの週報管理アシスタントです。
シート構成は次の通りです。1行目がヘッダー、2行目以降がデータです。

【M_大分類】大分類ID / 大分類名 / 表示順 / 色
【M_担当者】担当者ID / 担当者名 / 所属 / 表示順 / 在籍
【M_案件】案件ID / 案件名 / 大分類名 / 担当者名 / ステータス / 進捗率 / 取り組み内容 / コメント／課題 / 開始日 / 期限 / 完了日 / 累計作業時間
【T_タスク】タスクID / 案件名 / 区分 / 担当者名 / 大分類名 / 日付 / 作業内容 / 時間(h) / ステータス / コメント／課題

ルール:
- 「案件名」「大分類名」「担当者名」は必ず既存マスタ（M_案件 / M_大分類 / M_担当者）の値から選ぶ。新規の値を勝手に作らない。
- 「区分」は「予定」または「実績」のいずれか。
- 「日付」はyyyy-mm-dd形式。
- 円グラフ・時間集計は必ず T_タスク の「区分=実績」の行だけを対象にする。
```

## 1. タスク登録キャンバス（`T_タスク`へ行追加）

### プロンプトA：登録フォームを作る

```
（↑「0. 共通の前提ブロック」を先に貼る）

上記を前提に、T_タスク へタスクを1件ずつ登録できる入力フォームをキャンバス上に作ってください。

要件:
1. 入力項目と入力方法:
   - 案件名：M_案件 の案件名からプルダウン選択
   - 区分：「予定」「実績」のプルダウン
   - 担当者名：M_担当者 の担当者名からプルダウン選択
   - 大分類名：M_大分類 の大分類名からプルダウン選択
   - 日付：日付ピッカー（既定は今日）
   - 作業内容：テキスト入力
   - 時間(h)：数値入力（区分=予定なら見積時間、区分=実績なら実作業時間）
   - ステータス：「未着手」「進行中」「完了」のプルダウン
   - コメント／課題：テキスト入力（任意）
2. 「登録」ボタンを押すと、T_タスク の最終行の次に1行追加する。
3. タスクIDは「T-」+連番5桁（例 T-00001）で自動採番する。
4. 案件名・区分・担当者名・大分類名は必須。未入力ならエラー表示して登録しない。
5. 登録後はフォームをクリアし、「登録しました（タスクID）」と表示する。

■調整の指示例（必要なら追記）:
- 「実績を登録したら、その案件の M_案件.累計作業時間 が更新されることを確認したい」
- 「よく使う案件・大分類を上に表示して選びやすくして」
- 「連続入力しやすいよう、登録後も担当者名と日付は保持して」
```

### プロンプトA-2：新規案件も同時に登録できるようにする（任意）

```
（プロンプトAに続けて）

案件名のプルダウンに「＋新規案件」を追加してください。
これを選んだ場合は、案件名・大分類名・担当者名・期限を入力させ、
まず M_案件 に新しい行（案件ID「C-」+連番4桁を自動採番、ステータス=未着手、進捗率=0）を追加してから、
その案件に紐づく T_タスク の行を追加してください。
```

## 2. ダッシュボード表示キャンバス（円グラフ＋ドリルダウン）

### プロンプトB：ダッシュボードを作る

```
（↑「0. 共通の前提ブロック」を先に貼る）

上記を前提に、作業時間のダッシュボードをキャンバス上に作ってください。
対象は必ず T_タスク の「区分=実績」の行のみです。

構成:
1. 期間フィルタ:
   - 「日」「今週」「先週」「今月」「任意期間（開始・終了）」を切り替えられるようにする。
   - 既定は「今週」。
2. 大分類別の円グラフ:
   - 選択期間内の実績時間を「大分類名」で合計して円グラフにする。
   - 各扇形に 大分類名・時間(h)・割合(%) を表示する。
3. ドリルダウン:
   - 円グラフの扇形（大分類）をクリックすると、その大分類の実績を「案件名」ごとに合計し、
     時間の多い順に棒グラフ＋表で表示する。
   - さらに案件をクリックすると、その案件の実績明細（日付／担当者名／作業内容／時間(h)／コメント）を一覧表示する。
4. 担当者フィルタ:
   - 担当者名で全体を絞り込めるプルダウンを付ける（既定は「全員」）。
5. 数値サマリ:
   - 選択期間の「総実績時間」「案件数」「タスク件数」を上部にカードで表示する。

■調整の指示例（必要なら追記）:
- 「電話対応の割合が大きいときに一目で分かるよう、上位3分類を色で強調して」
- 「予定(見積)と実績の合計を並べて予実比較の棒グラフも出して」
- 「週ごとの推移を折れ線グラフでも見たい」
```

### プロンプトB-2：週報ビューを自動生成（任意）

```
（↑「0. 共通の前提ブロック」を先に貼る）

指定した「担当者名」と「対象週（月曜〜日曜）」について、週報を自動生成してください。
出力構成:
1. 取り組んだ内容：その週に実績（区分=実績）があった案件を一覧（案件名・取り組み内容・進捗率）
2. 日別の作業：日付ごとに 作業内容・大分類名・時間(h)・コメントを並べる
3. 課題・コメント：T_タスク と M_案件 のコメント／課題を集約
4. 進捗率：案件ごとの進捗率（M_案件から）
5. 未完了タスク：区分=予定 かつ ステータス≠完了 の一覧
6. 来週の予定：区分=予定 かつ 日付が翌週の一覧
7. 作業時間サマリ：大分類別の合計時間（円グラフ）
コピペで共有できるテキスト形式でも出力してください。
```

---

## 3. 運用のコツ

- **必ず「0. 共通の前提ブロック」を先頭に付ける**。付けないとキャンバスが列名・区分の意味を取り違えやすい。
- 登録は「名前」を選ぶ方式（マスタ参照）で統一する。フリー入力を許すと円グラフが割れる。
- 生成結果がずれたら、いきなり作り直さず「■調整の指示例」のように **差分だけ追記** して直すのが早い。
- まず **プロンプトA（登録）→ プロンプトB（ダッシュボード）** の順で作るのがおすすめ。
  （登録で実データが少し貯まると、ダッシュボードの生成精度が上がる）

---

## 4. 次のアクション

1. サンプルデータを数件 `T_タスク`（区分=実績）に入れる
2. プロンプトA でタスク登録キャンバスを作成 → 実際に数件登録
3. プロンプトB でダッシュボードを作成 → 円グラフ・ドリルダウンの動作確認
4. 表示・集計のズレを「■調整の指示例」で微調整
