# 週報スプレッドシート テーブル設計（確定版 v1）

## 0. この設計で実現したいこと（要件整理）

現状：週報が「Excelファイル単位（今週=ファイルA / 来週=ファイルB）× 人数分」で分散管理。

移行後にやりたいこと：

1. **1案件を1行**で、取り組み内容・コメント/課題・進捗率・予定（いつやるか）を記録したい
2. スプレッドシートの**キャンバス機能**からタスクを登録したい
3. 登録したタスクが**ダッシュボード**としてキャンバスに表示される
4. **作業時間**を記録し、日／週で**大分類ごとの円グラフ**を出したい
5. 円グラフの大分類（例：電話対応）で**絞り込み（ドリルダウン）**して、
   「どの案件／どのタスクに時間を取られたか」まで掘り下げたい

## 設計方針の決定事項（このv1で確定）

| 論点 | 決定 |
|------|------|
| 予定と実績 | **1テーブルに統合**（`T_タスク`＋`区分`列で予定/実績を区別） |
| 分類の階層 | **大分類のみ**（中分類・小分類は持たない） |
| 進捗率 | **手入力** |
| 担当者 | **`M_担当者`マスタを持つ**（人別集計を可能にする） |

---

## 1. 設計の核：「1案件1行（マスタ）」と「時間記録（明細）」は分ける

今回の設計で一番大事なポイント。

- ユーザーが望む **「1案件1行」** は、案件の“今の状態”を俯瞰する **マスタ（`M_案件`）** で実現。
- 一方 **作業時間** は「同じ案件を月・火・水…と複数日作業する」ため、時間の記録は複数行発生する。
- したがって時間は **明細テーブル（`T_タスク`）に1作業1行** で持つ。

→ この2つを **案件ID** で繋ぐことで、「1案件1行の一覧」と「時間の円グラフ／ドリルダウン」を両立します。

> 予定と実績は今回 **`T_タスク` に統合**（`区分`列）。予定＝これからやること、実績＝やったこと＋時間。

---

## 2. テーブル一覧（4テーブル構成）

| # | テーブル名 | 役割 | 粒度（1行の意味） |
|---|-----------|------|------------------|
| 1 | `M_案件` | 案件マスタ | 1案件 = 1行 |
| 2 | `T_タスク` | 予定＋実績の明細 | 1タスク（予定 or 実績の1件）= 1行 |
| 3 | `M_大分類` | 分類マスタ | 1分類 = 1行 |
| 4 | `M_担当者` | 担当者マスタ | 1人 = 1行 |

### テーブル間の関係（ER）

```
   M_大分類(大分類ID)        M_担当者(担当者ID)
        ▲   ▲                   ▲   ▲
        │   │                   │   │
        │   └──────┐    ┌───────┘   │
      M_案件        └ T_タスク ┘     │
     (案件ID) ◄──────(案件ID,        │
        ▲            大分類ID,       │
        │            担当者ID) ──────┘
        └──── T_タスク.案件ID で M_案件 を参照
```

- **案件ID** … 全テーブルをつなぐ結合の軸（`M_案件` ⇄ `T_タスク`）
- **大分類ID** … 円グラフの分類軸（`M_大分類`を参照）
- **担当者ID** … 人別集計の軸（`M_担当者`を参照）

## 3. テーブル定義

### 3-1. `M_案件`（案件マスタ）＝ 1案件1行

案件の“今の状態”を俯瞰する、ユーザーが望む「1案件1行」のビュー。

| 列名 | 型 | 例 | 説明 |
|------|----|----|------|
| 案件ID | ID(PK) | C-0001 | 一意キー。全結合の軸 |
| 案件名 | 文字 | ○○社 見積作成 | |
| 大分類ID | 参照 | K01 | `M_大分類`を参照（主となる分類） |
| 担当者ID | 参照 | U01 | `M_担当者`を参照（主担当） |
| ステータス | 選択 | 進行中 | 未着手／進行中／完了／保留 |
| 進捗率 | 数値% | 60 | **手入力** |
| 取り組み内容（概要） | 文字 | 要件ヒアリング〜見積 | 案件レベルの説明 |
| コメント／課題 | 文字 | 先方回答待ち | 案件レベルの課題 |
| 開始日 | 日付 | 2026-06-23 | |
| 期限 | 日付 | 2026-07-10 | |
| 完了日 | 日付 | | 完了時に記録 |
| 累計作業時間 | 数値h | 12.5 | `T_タスク`(区分=実績)から自動集計（SUMIFS） |

> 進捗率は手入力。累計作業時間だけは `T_タスク` から自動集計を推奨（手集計は事故のもと）。

---

### 3-2. `T_タスク`（予定＋実績の明細）＝ 1タスク1行  ★このテーブルが心臓部

**予定（これからやること）** と **実績（やったこと＋時間）** を、`区分`列で1テーブルに統合。
時間の円グラフ／ドリルダウンは、この表の **区分=実績** の行を集計して作ります。

| 列名 | 型 | 例 | 説明 |
|------|----|----|------|
| タスクID | ID(PK) | T-00001 | |
| 案件ID | 参照 | C-0001 | `M_案件`を参照（ドリルダウンの軸） |
| **区分** | 選択 | 実績 | **予定／実績**（このテーブルの肝） |
| 担当者ID | 参照 | U01 | `M_担当者`を参照 |
| 大分類ID | 参照 | K02 | `M_大分類`を参照。円グラフの軸 ※注 |
| 日付 | 日付 | 2026-06-30 | 予定=予定日／実績=作業日。日・週の集計軸 |
| 作業内容 | 文字 | 電話で仕様確認 | 予定＝やる予定の内容／実績＝やったこと |
| 時間(h) | 数値 | 1.5 | 予定＝見積時間／実績＝実作業時間。円グラフの値 |
| ステータス | 選択 | 完了 | 未着手／進行中／完了（主に予定行の管理用） |
| コメント／課題 | 文字 | 追加依頼あり | その作業の気づき |

**入力・運用ルール**
- 「これからやること」を登録 → **区分=予定** の行を追加（日付=予定日、時間=見積）
- 「やったこと＋時間」を記録 → **区分=実績** の行を追加（日付=作業日、時間=実時間）
- 予定を実施したら、区分=実績の行を新たに1行足す（複数日にまたがる作業も1日1行でOK）
- → これで **予実比較**（同一案件の 予定合計 vs 実績合計）も同じ表から出せる

> **※大分類IDを行ごとに持つ理由**：同じ案件でも日によって作業の性質が変わる
> （例：ある案件で「電話対応」も「資料作成」もする）。
> 「電話対応にどれだけ時間を使ったか」を正確に出すには **時間の行ごとに大分類が必要**。
> `M_案件` 側の大分類（案件の主分類）とは役割が違う点に注意。

---

### 3-3. `M_大分類`（分類マスタ）＝ 円グラフの分類軸を固定

**円グラフがブレない**ために必須。手入力の表記ゆれ（"電話"／"電話対応"／"TEL"）を防ぐ。

| 列名 | 型 | 例 | 説明 |
|------|----|----|------|
| 大分類ID | ID(PK) | K02 | |
| 大分類名 | 文字 | 電話対応 | 円グラフの凡例に出る名前 |
| 表示順 | 数値 | 2 | グラフの並び順 |
| 色 | 文字 | #4285F4 | （任意）円グラフの色固定 |

> `M_案件` と `T_タスク` の大分類列は、この表を**プルダウン（データの入力規則）**にする。
> 今回は大分類のみ（中分類・小分類は持たない）。

---

### 3-4. `M_担当者`（担当者マスタ）

人別の集計（誰が何にどれだけ時間を使ったか）を可能にする。

| 列名 | 型 | 例 | 説明 |
|------|----|----|------|
| 担当者ID | ID(PK) | U01 | |
| 担当者名 | 文字 | 山田太郎 | |
| 所属 | 文字 | 営業1課 | （任意） |
| 表示順 | 数値 | 1 | （任意） |
| 在籍 | 真偽 | TRUE | 退職者を集計から外す等（任意） |

> `M_案件`.担当者ID と `T_タスク`.担当者ID は、この表をプルダウン参照にする。

---

## 4. 全テーブルが繋がったダッシュボードは作れる？→ **はい、作れます**

条件は2つだけ：

1. **共通キー = 案件ID** を `M_案件` と `T_タスク` の両方に持たせる（結合の軸）
2. **大分類・担当者はマスタ参照（プルダウン）** にして表記を統一する（集計軸）

これが守られていれば、1つのダッシュボードから全部が連動します：

- 案件一覧（`M_案件`）で案件を選ぶ → その案件の予定・実績（`T_タスク`）が芋づる式に出る
- 大分類の円グラフ（`T_タスク`の区分=実績を大分類で集計）で分類を選ぶ → 該当案件が絞り込まれる
- 担当者で絞る → その人の時間内訳・案件が出る

崩れるとNGな例：
- 案件IDが無い／案件名頼み → 一覧と時間が連動しない
- 大分類・担当者がフリー入力 → 「電話対応」と「電話」が別扱いで円グラフ／集計が割れる

---

## 5. 作業時間の円グラフ＆ドリルダウン → 実現できます

### 元データ
すべて `T_タスク` の **区分=実績** の行（案件ID・日付・大分類ID・担当者ID・時間）から作る。

### ① 大分類別の円グラフ（日／週）
```
値   = SUM(時間)   ※ 区分=実績 のみ
分類 = 大分類名（M_大分類）
絞り = 日付 = 対象の日 / 対象の週
```
→ ピボット or `SUMIFS(時間, 区分,"実績", 大分類, 各分類, 日付, 期間)`。

### ② ドリルダウン（大分類 → 案件 → タスク）
```
[Lv1] 大分類で絞る（例：電話対応）
  ↓  T_タスク を 区分=実績 & 大分類=電話対応 でフィルタ
[Lv2] 案件ごとに時間を集計（どの案件に取られたか）
  ↓  GROUP BY 案件ID → SUM(時間) を棒グラフ/表で
[Lv3] 個別の作業明細（いつ・誰が・何を・何時間）
      該当行をそのまま表示
```

成立する理由：時間データが「案件ID＋大分類ID＋担当者ID＋時間」を **1行ずつ** 持っているから。
（1案件1行に時間を畳み込んでいたら、この掘り下げは不可能）

## 6. 週報としての“見せ方”（既存運用のマッピング）

| 既存の週報の要素 | 新設計での出どころ |
|-----------------|-------------------|
| 取り組んだ内容 | `M_案件`.取り組み内容 ＋ `T_タスク`(実績).作業内容 |
| その日やったこと | `T_タスク`（区分=実績・日付で絞る） |
| 課題・コメント | `M_案件`.コメント／`T_タスク`.コメント |
| 進捗率 | `M_案件`.進捗率（手入力） |
| 未完了タスク一覧 | `T_タスク`（区分=予定 & ステータス≠完了）／`M_案件`.ステータス≠完了 |
| 来週の予定 | `T_タスク`（区分=予定・日付が来週の行） |
| 作業時間・円グラフ | `T_タスク`（区分=実績）.時間 を大分類で集計 |

→ 週報は「テーブルから条件で切り出したビュー」になり、Excelを人数分×週数分作る運用が不要に。

## 7. キャンバス登録フローとの関係（概要）

キャンバスからの登録は **`T_タスク` への1行追加** に集約されます（予定/実績は`区分`で切替）。

- 「これからやること」を登録 → `T_タスク`（区分=予定）
- 「やったこと＋時間」を登録 → `T_タスク`（区分=実績）
- 新しい案件なら先に `M_案件` に1行

> 登録時のポイントは「**案件ID・大分類・担当者をプルダウンで選ばせる**」＝手入力させないこと。
> これがダッシュボード連結・円グラフ精度の生命線。登録用キャンバスのプロンプト設計は次ステップ。

---

## 8. 次のアクション（提案）

1. `M_大分類` の分類リストを実際の業務ベースで洗い出す（円グラフの軸になる）
2. `M_担当者` に部署メンバーを登録
3. 各テーブルをスプレッドシートのシートとして作成＋プルダウン設定
4. ダッシュボード（ピボット／円グラフ／ドリルダウン）を1枚作成
5. キャンバス登録用プロンプトを設計（別途）

> 補足：予実比較を「同一行で見たい」場合は、`T_タスク` に `見積時間` と `実績時間` を
> 分けて持つ変形案もあり。まずは `区分`＋単一 `時間` 列（本v1）でシンプルに始めるのを推奨。
